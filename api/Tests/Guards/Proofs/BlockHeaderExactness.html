    [162] c-b-block-header exactness (Rule 2 probes) #

    YAML 1.2.2 [162] is ([163] [164] | [164] [163]) s-b-comment: at most one chomping indicator (-/+) and at most one indentation indicator (1–9), in either order. Before this guard, parseBlockHeaderLoop consumed ANY two header characters, so |++, |--, |-+, |11, |1+, |+1, >-2, >2- were all accepted (lake exe tryparse, exit 0) while |0, |1 1, |10, |+++, |2+- were refused. peekBlockHeaderIndicator? now hides a repeated kind, so the second indicator is left for the header-end check to refuse; the surface production SCBBlockHeader is the spec shape and parseBlockHeaderLoop_prod derives it. Each probe runs BOTH pipelines, which must agree.
