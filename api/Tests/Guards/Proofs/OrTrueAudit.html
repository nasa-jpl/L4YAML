    The ∨ True audit (DOCS item 395) #

    The owner's directive on item 394: fix all ∨ True — I do not want to carry any such risk. A statement of the shape P ∨ True is unfalsifiable at the type: Or.inr trivial proves it, so a green build says nothing about P, and only the censuses' pins keep the informative side honest. PackAlt sc and PackAltG g are True by definition (item 311), so ∨ PackAlt … is the same shape under a name.

    This guard is the roster the retirement lane works from. It is read off the environment, not off a grep:

    • positions — every ∨ whose right alternative is True / PackAlt _ / PackAltG _ in the TYPE of any authored constant of any L4YAML.* module (a lemma's binder or conclusion, a constructor's field, a Prop definition's body), keyed by declaration and binder; top when the binder's own type is the disjunction, nested when it sits inside a binder's statement;
    • supply — for every top position declared in StreamAccum, what the module's own applications put there, read through RelaySupplyCensus.edges (PAY / DECLINE / RELAY / VIA / FIELD / SPLIT): paid when at least one PAY reaches it, relayed when only relays and splits do, declined-only when every edge is an Or.inr, never-supplied when no application in the module fills it;
    • writers — every declaration whose value writes Or.inr trivial (or Or.inr True.intro), with the count.

    Every pin is shrink-only: a retirement item re-pins a position DOWN with its disposition (paid, refuted, restated); a position that appears needs the owner's word in the item that adds it.
