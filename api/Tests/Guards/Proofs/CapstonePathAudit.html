    The ∨ True audit, ON or OFF the capstone's path (DOCS item 439) #

    The owner's reading of item 438: a ∨ True cannot make the capstone unsound, only weak; the risk he refuses to carry is the set of positions whose vacuous arm weakens a fact the capstone CONSUMES. This guard pins that set. It takes the ∨ True audit's pinned tables (OrTrueAudit.expectedPositions / expectedSupply / expectedConsumers) and the closure of constants DocumentProduction.scan_strict_proof / parse_strict_proof reach — the two capstones that import StreamAccum — and classes every position with Scripts.Path.CapstonePath.classify (the classes are documented there).

    Pins are shrink-only: the ON roster is re-pinned DOWN when an item pays or retires a position (it leaves the audit) or moves it OFF; a position that appears ON needs the owner's word in the item that adds it. The OFF roster is residue by class and is pinned exactly. lake run capstone-path recomputes the same reading off the built .oleans.
