    Rule-2 exhibit: : glued to a flow collection value after a non-JSON key #

    Spec [147] c-ns-flow-map-separate-value ::= ":" (s-separate(n,c) ns-flow-node(n,c) | e-node) requires s-separate between the : and a present value; the separator-free form is [149] c-ns-flow-map-adjacent-value, reachable only through [148] c-ns-flow-map-json-key-entry (a JSON-like key). With [66] s-separate-in-line narrowed to col 0 the Surface derivation of {a:[1]} has no arm: a is a yaml key, so [147] is the only entry, and nothing non-empty separates : from [.

    The scanner used to accept these (isValueCandidate's [147] branch takes a flow indicator after : as the value indicator and then scans the collection with no separator). scanValueValidate / scanValueValidateIx now refuse them (flowGluedCollectionValue, error unseparatedValue); the JSON-key shapes stay accepted. [148]/[149] themselves are not yet in L4YAML/Surface/Node.lean — companion gap.
