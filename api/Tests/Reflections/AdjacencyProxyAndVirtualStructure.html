    Reflection 615 — token adjacency is a proxy, and virtual structure breaks it #

    A scanner guard often wants to say "these two things belong to the same syntactic unit", and the cheapest thing at hand is token adjacency: token b came directly after token a, so they are part of one construct.

    That proxy is exact only where the grammar emits a token for every structural boundary. Where a boundary can open virtually — an indent, a scope, an implicit block — two adjacent tokens can belong to different units, and every "no legal document has X directly after Y" argument built on adjacency is false there. The fix is not to abandon the proxy but to gate the guard on the context in which no virtual opening is possible.

    The two halves #

    §2, soundness where the proxy holds. adjacency_exact_without_virtual_open: for every document built without a virtual open, two property tokens are never adjacent. So inside a flow collection, adjacency really does mean "one node's property run", and a guard may reject on it.

    §3, the counterexample where it does not. adjacency_fires_on_a_legal_document: proppedBlock propped — a property on a collection that itself opens virtually, containing a node that carries its own property — is a perfectly legal document whose token stream is [prop, prop, content]. The ungated guard rejects it.

    The method half (§4) #

    The counterexample was not in the hand-built probe list, and the reference implementation agreed with the over-strict guard on every input that list contained. Both facts have the same structural cause, and it is not bad luck: a probe list written while thinking about a guard inherits the guard's own blind spot. Here every hand-written case was flow-shaped, so handProbe_is_silent is forced — handProbe_has_no_virtual_open proves the list could not have refuted anything. The existing regression corpus — which contains shapes nobody was thinking about — is what refuted it: corpus_refutes_the_ungated_guard.

    Cheapest order, then: build the strictening, run the corpus you already compile, then reason further. A soundness argument of the form "no legal document has X adjacent to Y" is a claim about the whole corpus, so the corpus, not a fresh probe, is its natural refuter.
