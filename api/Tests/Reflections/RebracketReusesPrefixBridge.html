    Reflection 378 — a prefix-length positional bridge is reusable for ANY structured element by #

    re-association; the feared "close bridge" is the separator bridge with a re-bracketed prefix

    Self-contained core-Lean toy of L4YAML BRICK D's carved seq/seqEmpty CONS dispatch (nestedSeq_recseqentry_locate_seq_cons_step).

    A positional recursion already has a SEPARATOR bridge — "in pre ++ x :: tail, the token at index pre.length is x." Assembling the dispatch, a boundary-exclusion brick needs to read the CLOSE cl of a head entry op :: (interior ++ [cl]). That looks like a new "last-element bridge", but re-associate op :: (interior ++ [cl]) ++ rest = (op :: interior) ++ cl :: rest: now cl is the FIRST token past the op :: interior prefix, so the SAME separator bridge reads it with pre := op :: interior. One prefix-length bridge serves the head (prefix []), the close (prefix op :: interior), and the separator (prefix op :: (interior ++ [cl])) — the prefix choice selects the token, because the bridge is BLIND to the prefix's contents.

    source
    theorem Tests.Reflections.RebracketReusesPrefixBridge.prefix_read {α : Type} (pre tail : List α) (x : α) :
    (pre ++ x :: tail)[pre.length]? = some x

    The single PREFIX-LENGTH positional bridge. In pre ++ x :: tail, the element at index pre.length is x. It reads ONLY the prefix's LENGTH — never its contents — so re-associating a list to expose a different prefix re-aims the same lemma at a different token, for free.

    theorem Tests.Reflections.RebracketReusesPrefixBridge.rebracket {α : Type} (op cl : α) (interior rest : List α) :
    op :: (interior ++ [cl]) ++ rest = op :: interior ++ cl :: rest

    Re-bracketing a structured head block op :: (interior ++ [cl]) ++ rest exposes its CLOSE cl as the first token past the op :: interior prefix. Pure cons_append/append_assoc.

    NEGATIVE — a token with NO structural boundary at its index needs the INNER decomposition. #

    theorem Tests.Reflections.RebracketReusesPrefixBridge.read_interior_needs_inner {α : Type} (op i0 i1 : α) (irest rest : List α) :
    (op :: (i0 :: i1 :: irest ++ rest))[[op, i0].length]? = some i1

    Block re-association exposes prefixes of length 0 (head), (op::interior).length (close), and entry.length (separator) — the STRUCTURAL boundaries. A token strictly INSIDE interior sits at none of them: to read it the bridge needs a prefix of THAT length, which only interior's OWN decomposition provides. Re-associating the BLOCK alone never produces it — the bridge applies exactly where there is a boundary.
