    Scripts.Pins — def expected… := pins and the build log that moves them #

    The port of scripts/repin.py (plan Blueprint/09-scripts-in-lean.md §3 phase 2.1). Every guard under Tests/Guards/Proofs/ pins what its census counted as a literal (String, Nat, List String, List Name) and throws "<title>.\nexpected: {expectedFoo}\ngot: {got}" when the tree moves. This reads one lake build log, finds each expected:/got: block, locates the throwError whose message title matches, and rewrites the named def expected… : T := to what the build reported.

    One run is a FLOOR: a guard that throws on its first check never reaches its later ones, and a failing module blocks its dependents. Rebuild and re-run until the log reports no moved pin. Then read every change — a pin is a decision, and the script only does the typing.

    A pin whose literal carries comments between or after its entries is reported skipped and left for a hand edit. The got: line is Lean's toString, so a List String prints as [a, b] without quotes: elements are split on , ; an element that itself contains , is re-glued only when the OLD list had an element with the same prefix, and the result is flagged CHECK either way.

    Hand parsers for the Python's ERR_HEAD, NEXT_BLOCK, THROW, DEF regexes (plan §6 Q1: no regex dependency), each with its #guard rows.
