    Anchor Indexes #

    Hash indexes over the two anchor tables a parse state carries, so that the per-alias work in parseNode (§7.1's "does this anchor occur?") and in addAnchor (resolveAliases' first-match lookup) is O(1) instead of a scan of the whole table.

    Both indexes are proof-carrying structures: the hash structure is bundled with the proof that it agrees with the Array it indexes. The arrays stay the source of truth — every existing proof keeps reading ps.declaredAnchors and ps.anchors — and the index is a derived view that cannot drift, because the only constructors (empty, push) rebuild the agreement proof. The operations are @[irreducible] so that rfl/simp on parser states never unfold hash-map internals; proofs go through contains_eq_any and resolveAliasesWith_find? instead.

    • DeclaredIndex names: a HashSet with contains n ↔ n ∈ names.
    • AnchorIndex anchors: a HashMap from a name to the index of its first binding, with lookup = anchors.findSome? … — exactly the lookup YamlValue.resolveAliases performs.
    • YamlValue.resolveAliasesWith: resolveAliases over an abstract lookup function; resolveAliasesWith_anchorsLookup shows it is the same function when the lookup is the array's first-match scan.
