    Anchor/alias resolution lifted to documents and streams #

    Public wrappers and doc/stream-level lifts of the ParserNodeProofs scaffolding: capstones 3.5 parseNode_aliases_declared, 3.6 parseDocument_aliases_resolve, and 3.7 parseStream_output_aliases_resolve.

    The obligation has two readings and this file carries both #

    §7.1 forbids an alias whose anchor has not previously occurred; §3.2.2.2 says what an alias resolves to. Per node only the first is available: an anchor occurs at the & property, which is the node's start event, while its entry in the resolution table stores a value and so cannot exist until the node it decorates is complete. &x [*x] is exactly that gap — a legal document whose inner alias names an anchor that has occurred and is not yet resolvable — so capstone 3.5 is indexed on the DECLARATION set (AllAliasesDeclared).

    At a document boundary the two readings coincide, because every anchor the document declared has been finalized by the time its node returns. Capstones 3.6 and 3.7 are therefore stated on the resolution table, unchanged. AllAliasesResolve.of_declared is the step between the readings and AG.declsBound is what discharges its premise; DeclarationsBound is the document-entry condition, which the stream's initial state and parseStreamLoop's per-document reset both supply.
