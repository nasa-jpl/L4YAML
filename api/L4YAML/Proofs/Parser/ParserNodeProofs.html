    Per-function parser node proofs (anchors-grow / aliases-declared) #

    The per-function mutual-induction scaffolding (_ag, _aad families) behind capstones 3.4 parseNode_anchors_grow and 3.5 parseNode_aliases_declared: every parser clique member grows both anchor registers monotonically, leaves no name declared and unbound once its own node is finalized (AG), and admits an alias only for a name that has previously occurred (§7.1, AllAliasesDeclared).

    The per-node statement is indexed on the DECLARATION set and not on the resolution table, because those differ for exactly one shape: a collection's anchor occurs at its start event while its entry in the table stores a value and so cannot exist until its items are complete. &x [*x] is that shape, and ParserAnchorProofs recovers the resolution reading at the document boundary.

    Explicitly kept infrastructure per Blueprint/04-capstones.md ("Decomposition: what is not a capstone").

      AnchorsGrow relation #

      AG carries three facts about a parser segment, because the alias obligation needs all three and the same plumbing proves them:

      1. the RESOLUTION table only grows (anchorsGrow) — addAnchor's name → value map, written at node finalization;
      2. the DECLARATION set only grows (declsGrow) — §7.1's set of names that have occurred, written at the & property;
      3. every name the segment DECLARES is already BOUND when the segment ends (declsBound).

      The third is what lets a document boundary recover the resolution reading from the §7.1 reading, and it is the one that is not true of every segment: parseNodeProperties declares a name whose value cannot exist yet, which is all of row 20. That stage is therefore stated with AG0, the first two facts alone, and parseNode_ag_all re-establishes the third across the properties/finalization pair that parseNode itself forms — the one place in the clique where a declaration and its binding meet.

            The §7.1 reading, per node (AAD proofs) #

            The parse-side obligation is carried by AllAliasesDeclared over the DECLARATION set, not by AllAliasesResolve over the resolution table. The difference is one node: a collection's own anchor is declared at its start event and bound only once its items are complete, so &x [*x] has an alias whose name is declared and not yet resolvable. The resolution reading is recovered at the document boundary — parseDocument_aliases_resolve — where AG.declsBound says the two sets have met again.

            Every leaf of this clique is simpler than its resolution-indexed predecessor: the alias case IS the parser's guard, and finalization touches no declaration at all.
