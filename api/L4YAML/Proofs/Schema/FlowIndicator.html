    Flow Indicators Are Never Numbers #

    adaptForFlowContext double-quotes a plain scalar whose content contains a flow indicator (, [ ] { }). Under style-aware resolution a quoted scalar is a string, so for that rewrite to preserve resolve the content must already have been a string, i.e. no Core Schema spelling of null, bool, int or float may contain a flow indicator. This file proves that:

    resolveImplicit_of_hasFlowIndicator : hasFlowIndicator c.toList = true → resolveImplicit c = .str c

    by showing that every recognizer (isNull, isBool, isIntL, parseFloatL?) only accepts character lists drawn from a numeric alphabet with no indicator in it. The literal recognizers are finite case splits; the lexers are list inductions over isNatL.go, parseHex.go, parseOctal.go and splitOnChar.
