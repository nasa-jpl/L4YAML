    The cursor floor, carried at the token level (DOCS item 339) #

    Item 338 proved PendingKeySound.Sound through every scanNextToken arm but left one premise STARVED: after preprocessing, the cursor sits at or right of the current indent (PreprocessFloor). The unwind supplies it when an indent check was pending; when none was, it is a fact about the cursor the carrier did not hold. This module carries it:

    • ColFloor.floor — needIndentCheck = false → currentIndent ≤ col, in both contexts. Inside flow the scanner refuses under-indented content (underIndentedFlowContent in scanNextToken_dispatchStructural, underIndentedScalar in the scalar loops), so a flow close that returns to block level inherits a floor that already holds.
    • ColFloor.key / ColFloor.stack — every saved simple key (the live one and the ones stacked by flow openers) sits BEHIND the cursor, lexicographically on (line, col). The : arm spends it: scanValuePrepare opens a block mapping at the KEY's column, and the floor after the : needs that column at or left of the cursor. (KeysBehindCursor is the same fact on offsets; the push reads columns.)

    preprocessFloor is the bridge to item 338's premise; scanNextToken_colfloor carries the structure through one token so StreamAccum can thread both.
