    pendingKeys is stable through every non-writer scanner step (DOCS item 338) #

    ScannerState.pendingKeys is in lockstep with indents (item 335): the only writers are the four stack writers (unwindIndentsLoop, pushSequenceIndent, pushMappingIndent, scanValuePrepare), the two register writers that mark and settle a level (scanKey, scanValue) and the stale-key hook. Every other step leaves it alone, and this file says so lemma by lemma — each one the pendingKeys twin of an existing _preserves_pendingKeys lemma, so that PendingKeySound (the token-level carrier) can be transported through them.

    §9 The preprocess step leaves pendingKeys alone inside a flow (item 407) #
