    S5(→): the parser's anchor/tag guards compose to checkFrom #

    Capstone chain: 7.7 parse_iff_grammar, serialization half, via S5 of EVENTSOF-CONCEPT.md §9. The single-guard bridges (parser_alias_guard_exact, parser_tag_guard_exact) say what ONE guard checks at ONE token; this module composes them over a whole parseStream run.

    The checker is first restated as a state machine over tokens (stepTok, runToks), shown equal to checkFrom env (TokenEvents.go l pending). The parser-side invariant Rel is an ORDER, not an equivalence: the parser declares only the surviving anchor of a node (declareAnchorOpt props.anchor) and registers every %TAG handle, so its tables sit below (anchors) and above (handles) the Env the checker folds — which is exactly what the forward direction needs.

    Two token-shape facts the scanner guarantees but the parser does not re-check are premises here (both have token-level counterexamples, pinned in Tests/AdversarialInstantiation.lean, Priority 50): TagUsesShaped (a used handle is builtin or !word!) and DirectivesClosed (a directive run ends in ---). The run may also stop before the last token — at ...-less streamEnd or where parseDocument consumes nothing — so the conclusion is stated on the consumed prefix.
