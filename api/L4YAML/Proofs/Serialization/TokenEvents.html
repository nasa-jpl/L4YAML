    Serialization events of a token stream (EVENTSOF-CONCEPT §9, S2) #

    tokenEvents reads the scanner's token stream the way eventsOfSegs reads a lexical skeleton: anchors, aliases and shorthand tags become events in stream order, documentEnd is endDocument, and documentStart is beginDocument followed by the %TAG directives scanned before it (RuntimeScopes.documentEvents pins that order: the directives belong to the document the reset opens).

    It is executable and mentions no Prop; S3 proves the scan's skeleton witness has exactly this trace, S5 relates it to the parser's own anchor/tag checks.

              The algebra of go (S3 slice (2), item 463) #

              go is a fold with one piece of state, the named %TAG handles pending until the next ---. goOut is the same fold returning that state instead of flushing it, so a token list splits anywhere: go (l₁ ++ l₂) p = (goOut l₁ p).1 ++ go l₂ (goOut l₁ p).2. The scanner-arm bridges (TraceOf/DocBridge.lean) read the tokens an arm pushes through goOut.
