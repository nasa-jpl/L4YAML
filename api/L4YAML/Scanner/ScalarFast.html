    Scanner — Linear-time scalar loops #

    collectDoubleQuotedLoop, collectSingleQuotedLoop and collectPlainScalarLoop (Scalar.lean) are the specification loops: dozens of lemmas unfold them step by step. As executables they are quadratic in the number of line breaks of a multi-line scalar:

    • double-quoted rebuilds the kept prefix through a List Char at every fold (String.ofList (content.toList.take protectedLen));
    • single-quoted re-trims the whole accumulator at every fold (trimTrailingWS content);
    • plain keeps the pre-fold content alive for the no-gain rewind, so the content ++ folded append sees a shared string and copies it.

    This file gives each loop a twin that does the same work with a uniquely referenced accumulator, proves the twin equal to the specification loop, and registers the scanX equalities with @[csimp], so compiled code (the Lean API, native_decide, the FFI) runs the twins while every proof keeps reading the specification loops. Nothing observable changes: the csimp lemmas are kernel-checked equalities.

    • Quoted twins carry the accumulator as content ++ pending, where pending is the trailing white run a fold may trim — the double-quoted protectedLen is content.length, the single-quoted trimTrailingWS boundary is the content/pending split. A fold drops pending in O(1).
    • The plain twin remembers only the pre-fold length; on a no-gain rewind it rebuilds the pre-fold content from the (necessarily unextended) result. That happens at most once per scalar, so the scan stays linear.
